# Friend groups and group challenges

Existing accepted Inbox friends can join a new group immediately. Private conversation histories are never copied. Only the creator can add friends or change the icon; group access still requires active membership. Blocks are checked before grouping. Challenges require separate opt-in consent to share aggregate progress.

The first acceptance records a server deadline exactly 24 hours later. That deadline is also the challenge start. Weekly challenges last 7 elapsed days; monthly challenges last 30 elapsed days. Admission locks at the deadline. Logs get immutable server submission timestamps. Pre-start logs and old entries without timestamps do not count. Before editing/deleting a log after the end, the server freezes any due results. First-finisher ties use acceptance time and then stable user ID. Other race entrants need recorded progress for the small participation bonus. Big 3 races require the target reps for each lift, not a combined total. Fiber streaks require at least 25 g summed across that Eastern-time date's eligible meal logs.

Rewards are 500/1,000 XP, with 20/50 participation XP on weekly/monthly races. Award record IDs and summary message IDs are deterministic; settlement retries cannot duplicate rewards or chat reports. Finished results are immutable. Departed members are shown as withdrawn and earn no new challenge award. Public maintenance at /api/challenges/tick accepts no challenge IDs, timestamps, participants, XP, or other state changes. It only finalizes server-validated due challenges previously authorized by signed-in members, returns a processed count, and exposes no private data. Normal authenticated records/Inbox/challenge reads also settle due challenges. The linked Sites cloud schedule calls that maintenance endpoint while the site is closed.
